Nifty Seller Lite — v2.70.0_PRESSURE_INTEGRITY_SMART_ALERT_HARDENING

Purpose
- Harden Market Intelligence after 07-Oct live validation without loosening One Brain.
- Separate fast big-move risk detection from directional pressure quality.
- Distinguish fake/absorbed pressure from real pressure that already produced a move.

Key changes
1. Pressure Integrity Engine (shadow only, zero network)
   - Move Risk: NORMAL / WATCH / BUILDING / HIGH
   - Pressure Quality: UNVERIFIED / BUILDING / VERIFIED / REALIZED / ABSORPTION RISK / BUILD-UP FAILED / EXHAUSTING / FLIP WATCH / FLIP CONFIRMED
   - Move Attack: NORMAL / WATCH / BUILDING / ATTACK / BREAK-EXPANSION / rejection / flip states
   - Uses independent evidence families, price response, barriers, live market speed and existing cached evidence.
   - W/M and strong-candle patterns are supportive only; their absence never blocks an early warning.

2. Fast-warning latency protection
   - Big Move Watch can fire before pattern persistence/confirmation.
   - Direction is shown as tentative until quality improves.
   - High pressure does not equal a trade signal.

3. Fake vs real pressure
   - Strong pressure with no price progress + barrier/opposition -> ABSORPTION RISK.
   - A pressure wave that already moved price meaningfully becomes REALIZED; later collapse becomes EXHAUSTING rather than falsely marked fake.
   - Opposite direction first becomes FLIP WATCH; stronger independent confirmation is required for FLIP CONFIRMED.

4. Liquidity refinement
   - Distinguishes CURRENT BATTLE ZONE from NEXT HUNT ZONE.
   - First breach remains PENDING ACCEPTANCE.
   - Immediate reclaim/rejection is REVERSAL WATCH; REVERSAL FAVORED requires follow-through.

5. Smart Telegram alert arbitration
   - Market Intelligence is the primary alert voice.
   - W/M, candle and Big Player evidence remains calculated/recorded but is merged into the Market Intelligence alert context when that lane is enabled.
   - Material state changes (verified pressure, absorption, failure, flip, sweep, alignment/conflict) can alert without repeated same-setup pattern spam.

6. One Brain WAIT presentation
   - Backend WAIT logic is unchanged.
   - UI can show NO EDGE / WATCH / ARMED stages so an armed trigger is visible without weakening safety gates.

7. UI/data hardening
   - Core-block diagnostic table uses consistent display strings to prevent repeated PyArrow mixed numeric/string serialization errors.
   - FII/DII context shows as-of age for clarity.

8. Validation export
   - Adds pressure_integrity_review.csv and expanded quality/barrier/price-response/flip/liquidity-zone fields.

Explicitly NOT changed
- No new Dhan/broker API calls.
- No ML model added.
- No One Brain canonical weights/thresholds loosened.
- No change to decision.py, simple_brain.py, future_brain.py, execution_guard.py, trade_plan.py, position_guardian.py, or snapshot_service.py.
- No 15:15 spot-freeze guard was added; user requested this broker-side late-session behavior be ignored.
- No guaranteed probability/profit language.
